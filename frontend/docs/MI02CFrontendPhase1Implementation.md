## Implemented flow

Existing Warehouse Map → choose UTC start/term → inspect and explicitly select1–100 Cells → persistent basket across racks/zones → Buy dialog → real quote → explicit confirmation → fresh eligibility/availability/quote validation → real Managed create → existing reservation detail → existing Manager approval/owned contract signature/explicit development Managed mock payment.

Inspection never selects a Cell. Basket survives rack deep-link navigation within the same in-memory session/facility. Different facility/token clears it; logout cleanup clears it. Browser reload discards UI basket. No reservation/payment records or token-storage changes are introduced. An uncertain creation attempt is retained in memory when returning through rack navigation and cannot silently submit again.

Cell purchase requires known AVAILABLE operational/booking/display state, AVAILABLE parent Rack, zero actual kg/m³, positive measured width/depth/usableHeight, valid requested future interval, same facility and unique IDs. Reserved/occupied/blocked/maintenance/unknown Cells remain inspectable but cannot be booked; Yours does not override availability. Selected and inspected styles are separate; textual ownership/status/selection labels accompany colors. Existing floorplan, zoom/fullscreen, tooltip/drawer/navigation and animations remain.

Basket shows actual facility/code/rack/zone/level/dimensions/geometric volume. No arbitrary Cell allocation,weight-as-volume or nominal-height inference. Actual body uses unrounded numeric sum of configured dimensions; display rounds to6 decimals. Server tolerance1e-6 remains authoritative.

Popup reuses existing shadcn Button/Input/Checkbox and the project's native showModal pattern through a new isolated UI Dialog (no Radix dialog dependency currently installed). Native modality traps focus; Escape/close returns focus, pending operations prevent closure. Popup/list scroll on small screens; no horizontal overflow at five tested widths. Green/orange design retained without global redesign or package changes.

## Date availability and cache

Exact backend calendar semantics reproduced in an isolated helper:positive DAY/MONTH/YEAR term,UTC midnight start,calendar month/year clamp to target month's last day. canonical timestamps include milliseconds. Explicit old-record ranges can browse,while new purchase requires start/term computation matching range. Empty or invalid term disables purchase.

Map/rack loaders depend on range,using the existing abort/stale-request protections. Rack cache key includes facility,rack,interval and access-token session. Basket rows carry availability interval;date change immediately invalidates it and quote/consent,and refreshes selected racks. Invalid/missing/changed Cells remain visible with reason until deselected/refreshed. Pre-submit retrievesall selected racks fresh for exact interval and recomputes volume. Focus/refresh/lifecycle events clear cache and refresh. Returning from lifecycle remounts/fetches fresh data;deep links keep interval context. No timer polling or global cached private data.

## Errors, duplicate protection and uncertainty

Synchronous busy ref serializes quote/create/reconcile and prevents duplicate click/concurrent create. Preflight verifies current Customer profile,selected racks,volume and quote,then snapshots own known reservation IDs before the POST.

- 400:invalid body/capacity;refresh/requote;consent cleared.
- 401:existing authentication interceptor/route handling preserved;no token workaround.
- 403:verification/role unavailable;no create eligibility bypass.
- 404:facility/Cell/config unavailable.
- 409:availability/pricing/state conflict;refresh/requote;server decides final allocation.
- Network/5xx/malformed POST result:uncertain state;no automatic second POST. Explicit **Check booking result** GETs own records,excludes baseline known IDs and matches actual selection/facility/dates/capacity. Exactly one match navigates to real record. Multiple matches or failed read remains blocked. No match allows only a fresh availability/quote/explicit-confirmation manual retry,with explanatory message. GET absence is not claimed as a database noncommit guarantee;server transaction/conflict validation remains final.

Frontend busy flags are not cross-customer locking guarantees. Creation uses verified backend's transaction design;live DB race behavior remains unverified.

## B. Interactive features

- Zone buttons highlight and scroll to their sections. Selecting a filtered-out Zone clears the search so it can be focused. Rack selection also highlights its owning Zone.
- Rack blocks use the existing warehouseAxis utility and actual mapX/mapY/orientation, including sparse/non-zero coordinates and condensed large gaps. Labels explicitly distinguish grid positions from meters. The whole map stays visible during detail requests/errors.
- Selecting a rack loads only that rack's authenticated detail, in place. Levels sort descending and Cells ascending. Deep Rack URLs open the same dashboard context; an inspector link retains direct Rack navigation.
- Cells are semantic buttons with status text/color, 180 ms hover/focus glow, persistent selection, keyboard Enter/Space and touch support. Hover/focus opens a fixed-position, viewport-clamped portal tooltip with actual Cell/Zone/Aisle/Rack/Level/capacity/dimension/baseline fields. Missing usable clearance is not inferred. Escape/blur/clearing selection closes the tooltip; selected desktop cells may pin it.
- Clicking a Cell updates the desktop inspector. Tablet/mobile use a non-modal bottom drawer, leaving the map visible; tapping suppresses the duplicate hover tooltip. Clear Cell returns to Rack information. Escape closes details.
- Zoom uses bounded 60–180% transforms with measured scroll extents; Reset View restores zoom and pan. Drag blank canvas space to pan, use native touch scroll or keyboard scroll. Buttons are excluded from drag initiation.
- Fullscreen uses the native browser API; unavailable/rejected fullscreen falls back to an expanded dashboard with a clear status message and Exit/Escape controls.
- Refresh invalidates the current cache and reloads overview/selected detail. Last updated reflects a successful overview response, not a live/realtime claim.
- Search examines loaded Zones/Aisles/Racks and cached Cell records only; no inventory/product search or eager detail fetching.

## D. API integration and data accuracy

Reuse of unchanged services:

- `GET /api/v1/warehouse-map?facilityId=...` via warehouseMapApi and existing authenticated axiosClient.
- `GET /api/v1/racks/:id/detail-map` on selection/direct Rack URL via the same service/client.
- Existing public Facility Detail read for its name/context.

Existing response envelope/record validation and warehouse ownership checks are reused. Abort signals and current-token guards prevent obsolete selections/sessions from writing cache/UI. Detail results are cached only inside the mounted facility/current-session dashboard; changing token/facility unmounts and clears the cache. Refresh clears it. Re-selecting a cached rack produces no repeated detail HTTP call. There is no persisted cache or speculative fetching of every rack.

Zone/Rack counts derive from returned arrays. Cells/Available Cells sum actual cellCount/availableCellCount only when every rack supplies valid aggregate counts. Blocked/Maintenance totals show **Not available** because overview does not supply complete counts; available counts are not subtracted to invent per-status totals. No occupancy percentage, product totals, overload count or physical vacancy is inferred. Weights/capacities/dimensions are returned values, and all usage is labeled MI-01 baseline.

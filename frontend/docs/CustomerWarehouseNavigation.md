## C. Routes and APIs

| Route | Behavior |
| --- | --- |
| `/portal/warehouse-map` (new) | Select an active Managed Inventory facility |
| `/portal/warehouse-map/:facilityId` (existing) | Existing coordinate-based read-only overview; back to selection |
| `/portal/warehouse-map/:facilityId/racks/:rackId` (existing) | Existing Rack Detail; back to its facility map |

Selection calls existing `facilityApi.publicList` with `serviceType=MANAGED_INVENTORY`, page and limit=6. Current Backend PublicCatalogService filters ACTIVE/not-deleted records, but its sanitized public DTO does not expose status. Frontend verifies returned serviceTypes when available and rejects an explicitly non-ACTIVE status if returned; it does not invent a status field. Returned pagination is used for Previous/Next, with loading, empty, malformed response and error/retry states.

Overview/detail retain authenticated GET `/warehouse-map?facilityId=...` and GET `/racks/:id/detail-map` through the unchanged client. Existing public detail reads supply facility names in breadcrumbs. No management or mutation endpoint was added.

## D. Authentication

CustomerGate already preserves the requested pathname in React Router `location.state.from`; it was not rewritten. Login previously ignored it and sent Customers to /portal. After the existing successful login/profile refresh, Login now accepts only the exact warehouse selection path, a map path with a 24-hex facility ID, or a rack path with 24-hex facility/rack IDs, and only for role CUSTOMER.

External/protocol-relative URLs, other-role paths, invalid IDs, whitespace, traversal, query redirect payloads and non-string values fail the allowlist and use the original /portal fallback. No URL is evaluated as an arbitrary redirect. Manager and Staff retain their existing dashboard redirects; Admin/BOM retain the pre-existing /portal fallback. No other-role redirect was expanded or fixed as part of this task. Token storage/login requests/logout behavior are unchanged.

Selection, map and Rack direct URLs all use the existing guard; no protected map/detail request is issued before signing in. Already authenticated Customers use the existing session directly. Only Warehouse Map destinations are restored, so unrelated post-login routing stays as before.
